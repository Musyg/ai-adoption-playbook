# Contributing

Contributions should make the playbook more verifiable, usable or current.

## Good contributions

- a correction backed by a primary source;
- an anonymized field lesson with the context and limits stated;
- a reusable template with clear inputs and exit criteria;
- a translation that preserves meaning rather than word order;
- an accessibility, security or reproducibility improvement.

## Before opening a pull request

1. Keep one concern per pull request.
2. Date volatile legal, regulatory and vendor claims.
3. Separate requirements, guidance and project recommendations.
4. Do not paste copyrighted standards or confidential organizational material.
5. Run `python scripts/validate.py`.

Pull requests should explain what changed, why, who benefits and how the change was checked.
